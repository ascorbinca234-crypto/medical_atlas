# Защита материалов: реализация и ввод в эксплуатацию

Состояние: 18 октября 2026 года. Сервер обновлён в Яндекс Облаке: функция `atlas-api` (`d4e0lpca7eq568567g0m`), версия `d4eau56r3noj4eh5u185`, 12:44 МСК. Проверка `/health` вернула HTTP 200, `database:true`, все три `content:true` и новые политики. Старые и новый адреса материалов без авторизации возвращают 401. Первый запрос готовности после запуска вернул временный отказ YDB; повторная проверка прошла. Проверки выдачи с правами, отзыва и лимитов выполнены локально; на рабочем сервере они ещё не проверены под отдельным платным аккаунтом. Сайт публикуется совместно с этой записью; факт его публикации фиксируется отдельно в локальном отчёте.

## Что реализовано

- Закрытая выдача: `GET /content-v3/<предмет>/<тема>`. Токен, существующий аккаунт, его версия сессии и действующее право на конкретный предмет проверяются на сервере. Право повторно проверяется после резервирования лимита.
- Старые `/content/<предмет>` и `/content-v2/<предмет>` не возвращают материалы: 401 без входа, 403 без права, 410 при действующем праве. Обойти разбиение через прежний полный пакет нельзя на обновлённом сервере.
- 173 независимых пакета: фармакология — 29 конспектов/листов; биохимия — 10 разделов веществ, 4 пути, 5 анимаций; микробиология — 22 темы и 103 досье. В тему включены необходимые связанные карточки, рецепты, реакции и вопросы. Полные исходники сохраняются в закрытой папке; служебные монолитные результаты сборки не попадают в архив функции.
- Клиент получает только выбранную тему. При переходе к другой теме загружает новый документ и заново проверяет доступ. Поиск, тренажёры и инструменты работают с материалами текущей темы; выбор другой темы доступен в каталоге. Нет предварительной загрузки всего предмета.
- Материал не читается и не записывается в IndexedDB, localStorage или Cache Storage. Удаляется прежняя база `ma-content` и одноимённые кэши. Ответы имеют `private, no-store`; персональный ответ не разделяется между пользователями. Выход, истечение подписки, возврат из bfcache и неуспешная повторная проверка скрывают закрытую страницу и перезагружают её.
- Проверка прав при возврате к вкладке и раз в минуту. Для уже открытого документа отзыв на сервере выявляется при следующей проверке, а для следующей выдачи — сразу. Скриншоты, ранее сохранённые файлы и изменённый пользователем клиент отозвать невозможно.
- Персональная метка в коде выдачи, на странице и в печатном представлении: код аккаунта (HMAC), случайный код выдачи, время, предмет и тема. Сырой email, имя, IP и платёжные данные в метку не включаются. Это средство разбора распространения, не неустранимый DRM и не единственное доказательство нарушения.
- Лимиты аккаунта в скользящих окнах: 12 выдач/минуту, 80/час, 250/24 часа, 32 МиБ/24 часа по размеру исходного пакета до gzip. Повторные загрузки учитываются. Все вкладки и экземпляры функции используют один документ с условной записью версии. При гонке или недоступности БД выдача не разрешается без учёта лимита. 429 включает `Retry-After` и понятное сообщение.
- Прогресс по незагруженным темам сохраняется: частичный набор материалов не заменяет остальные разделы нулями.

## Сборка и проверки

Полная сборка требует внешнюю закрытую папку. Не добавлять её в публичный репозиторий.

```sh
ATLAS_PRIVATE=/path/to/medical_atlas_private python3 build.py --full
node --test server/test/*.test.js
ATLAS_PRIVATE=/path/to/medical_atlas_private node server/scripts/package.js
python3 scripts/export_public_site.py
python3 scripts/audit_public_history.py
```

Результаты: `server/dist/function.zip` содержит сервер и только отдельные темы; `outputs/medical_atlas_public_site.zip` содержит публичный сайт без API, закрытых материалов и истории Git. `outputs/public-site-manifest.json` фиксирует хэши файлов. Архив функции конфиденциален, его нельзя помещать в публичный Git, публичные Releases или общедоступное хранилище.

Дополнительная проверка в браузере: `node server/test/browser-topics.cjs` при доступном пакете Playwright; переменная `ATLAS_BROWSER` задаёт путь к локальному Chrome. Используется отдельный профиль, локальный сайт и тестовый аккаунт в памяти. Реальный API не вызывается. `ATLAS_SMOKE=1` оставляет короткую проверку переходов. Файлы `outputs/*-topic.png` — снимки тестовых страниц.

Обычная публичная сборка `python3 build.py` использует только пробные конспекты и каталоги заголовков. Полная проверка приватных пакетов запускается, когда они собраны; остальные тесты работают и без закрытой папки.

## Выкладка сервера

1. В существующую Yandex Cloud Function загрузить новый `server/dist/function.zip`. Сохранить переменные окружения, сервисный аккаунт, базу YDB и существующий шлюз. Новых секретов и таблиц не нужно.
2. Проверить `/health`: HTTP 200, `ok:true`, `policy:subject-subscription-v1`, `delivery:topic-delivery-v1`, `database:true` и три `content`-значения `true`.
3. На отдельном тестовом аккаунте проверить: отсутствие права → 403; право только на один предмет → тема этого предмета 200, чужой 403; отзыв → 403; обе старые версии выдачи → 410 при действующем праве.
4. Открыть одну платную тему в браузере: видна метка, загружается ровно один `/content-v3/…/…`, другие темы отсутствуют в ответе. После перехода меняется код выдачи. После выхода и возврата назад материал не восстанавливается из кэша.
5. Только после этого публиковать новый сайт. При старом API новый клиент показывает пробную версию и ошибку загрузки выбранной закрытой темы.

Без обновления функции старый API продолжает действовать по старым правилам; изменение одного сайта этого не исправляет.

## Хранение технического журнала

Документ `delivery:<код аккаунта из метки>` хранит внутренний `userId` и до 250 последних учитываемых событий. В YDB это `doc:delivery:…` в таблице users. Он доступен только серверу/администратору; публичного API для чтения нет. Случайный код выдачи сверяется с полем `r` события. Метка позволяет найти аккаунт, но не доказывает, кто именно распространил копию.

События старше суток отбрасываются при следующей выдаче. У неактивного аккаунта прежний ограниченный журнал остаётся до следующей выдачи или удаления аккаунта; фоновое удаление по сроку пока не настроено. Удаление аккаунта удаляет этот документ и права. Перед утверждением политики данных установить согласованный срок хранения и, если нужен строгий календарный срок, добавить плановую очистку. Не обещать автоматическое удаление ровно через сутки.
