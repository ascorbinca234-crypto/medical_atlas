# Старые материалы в GitHub: подготовленное решение

18 октября 2026 года. Репозиторий `ascorbinca234-crypto/medical_atlas` публичный. Через подключённый GitHub подтверждены `push:true`, `admin:false`, `maintain:false`: изменить видимость от имени текущего подключения нельзя.

## Выбранный технический вариант

Сохранить прежний репозиторий с историей как закрытый архив и создать чистый публичный репозиторий для сайта. Готовый набор публикации — `outputs/medical_atlas_public_site.zip`; в нём 14 файлов сайта, нет `.git`, закрытых тем, API, базы данных и архивов функции. Содержимое архива проверяется по `outputs/public-site-manifest.json`.

Это сохраняет историю для владельца и убирает её из обычного публичного просмотра без принудительной перезаписи рабочих веток. Выполняет владелец с правами администратора. Убедиться, что текущие условия GitHub позволяют выбранную конфигурацию Pages; сайт из закрытого репозитория может перестать публиковаться. Смена репозиториев предполагает короткое окно недоступности сайта, поэтому проводить её после обновления API и проверки чистой публикации.

## Действия владельца

1. Сохранить закрытую резервную копию репозитория со всеми нужными ветками и тегами, а также отдельно закрытые исходники. Не выкладывать архив истории в публичные Releases. Согласовать момент переключения с разработчиками и временно остановить публикацию.
2. Проверить публичные форки, открытые/закрытые PR, Releases, вложения, Actions artifacts и прежние развёртывания. Локальный отчёт `outputs/history-audit.json` покрывает известные локальные refs и пути, но не является полной инвентаризацией объектов GitHub.
3. В Settings → General → Danger Zone перевести прежний репозиторий в private, затем переименовать его, например в `medical_atlas_archive_private`. Проверить, что старые полные исходники и коммиты больше не открываются анонимно. Проверить старую публикацию Pages отдельно.
4. Создать **новый пустой публичный** репозиторий `medical_atlas` в том же аккаунте. Загрузить в него только распакованное содержимое `medical_atlas_public_site.zip` в корень. Не клонировать прежний репозиторий в новый и не импортировать его историю. Включить Pages для ветки публикации и корневой папки.
5. Проверить исходный адрес сайта, вход, кабинет, две пробные темы, а для тестовой подписки — новую выдачу тем. Если путь или домен отличаются, обновить `SITE_URL`, разрешённые origins и настройки OAuth до переключения пользователей.
6. Для дальнейшей разработки использовать закрытый репозиторий. В публичный репозиторий передавать только проверенный экспорт сайта. Для каждой отправки соблюдать `agent.md`: сначала успешный pull соответствующей ветки и проверка изменений. Не переносить старые ветки merge/push в чистый репозиторий.
7. Удалить собственные публичные копии материалов в Releases, artifacts и других местах, если они обнаружены. С владельцами сторонних копий вопрос решается отдельно. При неправомерной публикации использовать предусмотренные GitHub способы обращения правообладателя после проверки прав на материалы.

## Почему не выбран обычный force-push

В публичной истории встречаются не только удалённые JS/JSON, но и старые `index.html` с встроенным полным содержимым, шаблоны и изображение биохимии. Очистка только 18 удалённых файлов недостаточна. Переписывание веток меняет хэши коммитов, затрагивает PR и может быть отменено последующим push из старого клона. GitHub также может сохранять ссылки на коммиты и кэшированные представления.

Если владелец предпочитает очистку истории на месте, нужен отдельный согласованный запуск `git-filter-repo` на свежем зеркале с проверкой всех веток, тегов и переименованных путей; затем восстановление проверенной текущей публичной версии и согласованная принудительная отправка. В этой работе force-push не выполнялся.

## Что останется ограничением

Смена видимости и новый репозиторий не уничтожают чужие клоны, ранее скачанные файлы, скриншоты и публичные форки. Публичные форки при смене видимости исходного репозитория могут остаться публичными и отделиться от него. GitHub Support не гарантирует удаление обычных учебных материалов как «секретных данных». Уже предоставленные лицензии не аннулируются задним числом.

Пункт об истории нельзя считать завершённым, пока владелец не выполнит переключение и не будет сделана анонимная проверка старых URL, веток, PR, форков и публикаций. На момент подготовки файлов история на GitHub не изменялась.
