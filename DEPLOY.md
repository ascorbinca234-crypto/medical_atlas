# Вход и закрытые темы: как развернуть

Сайт остаётся на GitHub Pages. Вход и выдача закрытых тем работают в Яндекс Облаке: функция, API-шлюз и база YDB. Данные пользователей хранятся в России.

```
браузер ──► GitHub Pages: хаб, атласы (открытая часть), страница входа auth/
   │
   └──────► API-шлюз ──► функция atlas-api ──► YDB (пользователи)
                              │                 почта (письма)
                              └── закрытые части атласов (внутри функции)
```

Способы входа: почта и пароль, Яндекс ID, VK ID. Google и Apple не подключаются: с 7 июля 2026 года за них штрафуют (ст. 13.55 КоАП).

## Что где лежит

| Путь | Что это |
|---|---|
| `index.html` | Главная: лендинг со встроенным входом, интерактивной схемой и заявкой для преподавателей |
| `landing/` | Стили главной (Tailwind 4). После правок классов в `index.html`: `npm i -D tailwindcss@4`, затем `node landing/build.mjs` |
| `assets/team/` | Фото команды |
| `auth/` | Страница входа и регистрации, `auth.js` — общий клиент входа, `config.js` — адрес API |
| `privacy.html` | Политика конфиденциальности и текст согласия. **Заполните места, выделенные жёлтым** |
| `server/` | API без сторонних зависимостей (Node.js 18+) |
| `server/content/` | Закрытые части атласов. Создаются при сборке, в git не попадают |
| `farma-atlas/src/` | Открытые исходники фармакологии: лекции 1–3, листы I–VI, код |
| `biochem-atlas/data/` | Открытые данные биохимии: аминокислоты, углеводы, ЦТК и нужные им коферменты |
| `medical_atlas_private` | **Отдельный закрытый репозиторий**: остальные лекции, листы, вещества, реакции, пути и анимации |

Закрытый репозиторий кладётся рядом с публичным:

```
projects/
  medical_atlas/            ← этот репозиторий (публичный)
  medical_atlas_private/    ← закрытый
```

Другой путь можно задать переменной `ATLAS_PRIVATE=/путь/к/medical_atlas_private`.

## 1. Закрытый репозиторий

1. На GitHub создайте **Private** репозиторий `medical_atlas_private`.
2. Загрузите туда содержимое архива `medical_atlas_private.zip`.
3. Склонируйте его рядом с `medical_atlas`.

Править закрытые темы нужно там же, в тех же форматах, что и раньше:

- фармакология: `farma-atlas/src/k_*.js` — лекции, `*.locked.js` — закрытые листы, досье, дозы и модель «Организм»;
- биохимия: `biochem-atlas/data/*.json` — записи с полем `at` (место в общем списке), `biochem-atlas/src/locked.js` — пути и анимации.

## 2. Яндекс Облако

На Windows всё из этого раздела и раздела 6 делает скрипт `server/deploy/deploy.ps1`: положите рядом с ним `function.zip` и запустите `powershell -ExecutionPolicy Bypass -File deploy.ps1` (нужна программа `yc` после `yc init`). Ключи и пароли он хранит только на этом компьютере. Таблицы в базе сервер создаёт сам при первом запросе.

Вручную:

Нужен аккаунт в [console.yandex.cloud](https://console.yandex.cloud) с платёжным аккаунтом. Для небольшого проекта бесплатных лимитов Cloud Functions, API Gateway и YDB Serverless обычно хватает.

1. **Сервисный аккаунт** `atlas-api` с ролями `ydb.editor` и `functions.functionInvoker`.
2. **База** → Managed Service for YDB → «Создать базу», тип **Serverless**. На странице базы скопируйте **эндпоинт Document API** (`https://docapi.serverless.yandexcloud.net/ru-central1/…`).
3. **Статический ключ доступа** для `atlas-api`: «Сервисные аккаунты» → `atlas-api` → «Создать новый ключ» → «Статический ключ доступа». Сохраните идентификатор и секрет.
4. **Таблицы** — один раз, на своём компьютере:
   ```bash
   cd server
   YDB_DOCAPI_ENDPOINT=… YDB_ACCESS_KEY_ID=… YDB_SECRET_ACCESS_KEY=… node scripts/create-tables.js
   ```
5. **Функция** → Cloud Functions → «Создать функцию» `atlas-api`. Среда — `nodejs22`, точка входа `index.handler`, память 256 МБ, таймаут 30 с (отправка письма может занять несколько секунд). Код — архив `server/dist/function.zip` (как его собрать — в разделе 6).
6. **API-шлюз** → API Gateway → «Создать». Спецификация — из `server/api-gateway.yaml`, подставьте ID функции и ID сервисного аккаунта. После создания скопируйте домен шлюза вида `https://xxxx.apigw.yandexcloud.net` — это **API_URL**.

## 3. Яндекс ID

1. [oauth.yandex.ru](https://oauth.yandex.ru) → «Создать приложение» → «Веб-сервисы».
2. Redirect URI: `API_URL/auth/yandex/callback`.
3. Доступы: адрес почты, логин и имя, портрет пользователя.
4. Скопируйте ClientID и Client secret.

## 4. VK ID

1. [id.vk.com](https://id.vk.com/about/business/go) → кабинет → «Добавить приложение» → Web.
2. Базовый домен: домен API-шлюза без `https://` (`xxxx.apigw.yandexcloud.net`) — VK требует, чтобы он совпадал с доменом redirect. Доверенный Redirect URL: `API_URL/auth/vk/callback`.
   Профиль бизнеса в VK Бизнес ID нужно подтвердить в течение 60 дней, иначе приложение заблокируют.
3. Включите доступ к почте. Если VK не отдаст почту, аккаунт всё равно создастся, просто без адреса.
4. Скопируйте ID приложения.

## 5. Почта для писем

1. Заведите ящик на Яндексе, например `atlas.noreply@yandex.ru`.
2. Настройки почты → «Почтовые программы» → разрешите доступ по IMAP/SMTP.
3. [id.yandex.ru](https://id.yandex.ru) → «Безопасность» → «Пароли приложений» → пароль для почты.

Когда у проекта появится свой домен, письма лучше перевести на Yandex Cloud Postbox.

## 6. Переменные функции и выкладка

В настройках функции задайте переменные окружения. Секреты лучше хранить в Lockbox и подключать к функции оттуда.

| Переменная | Значение |
|---|---|
| `SITE_URL` | `https://ascorbinca234-crypto.github.io/medical_atlas` |
| `API_URL` | домен API-шлюза |
| `SECRET` | случайная строка от 32 символов: `openssl rand -base64 48`. Смена выкидывает всех из аккаунтов |
| `YDB_DOCAPI_ENDPOINT`, `YDB_ACCESS_KEY_ID`, `YDB_SECRET_ACCESS_KEY` | из шагов 2–3 |
| `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` | из шага 3 |
| `VK_CLIENT_ID` | из шага 4 |
| `SMTP_USER`, `SMTP_PASS` | ящик и пароль приложения из шага 5 |
| `LEAD_TO` | необязательно: куда приходят заявки преподавателей с главной. По умолчанию — тот же ящик `SMTP_USER` |

Сборка и выкладка после любой правки тем:

```bash
cd farma-atlas && python3 build.py && cd ..
cd biochem-atlas && python3 build.py && cd ..
cd server && node scripts/package.js      # → server/dist/function.zip
```

Загрузите `function.zip` новой версией функции. Публичные `index.html` атласов закоммитьте в этот репозиторий.

Проверка: откройте `API_URL/health`. Должно быть `"ok": true`. Если нет, в `missing` перечислено, чего не хватает.

В том же ответе `providers` показывает, какие входы включены. `"vk": false` значит, что в выложенной версии функции нет `VK_CLIENT_ID`: в `deploy.ps1` на вопросе «ID приложения VK ID» введите ID приложения.

Если письмо с кодом не дошло, причина видна на экране ввода кода («Подробности для разработчика») и в логах функции (строка `mail failed`). Каждое письмо приходит с новым кодом; действуют три последних.

## 7. Включить вход на сайте

В `auth/config.js` впишите адрес шлюза:

```js
window.MA_CONFIG = { api: 'https://xxxx.apigw.yandexcloud.net' };
```

Закоммитьте и отправьте на GitHub. Пока строка пустая, кнопки входа не показываются.

## 8. Старые версии в истории git

Раньше весь контент лежал в этом публичном репозитории, поэтому он остаётся в истории коммитов. Убрать его можно двумя способами:

- **Переписать историю.** Оставить один коммит с текущим состоянием и отправить его через `git push --force`. Это необратимо: старые коммиты исчезнут для всех.
- **Новый публичный репозиторий.** Создать его с чистой историей, включить в нём Pages, а старый удалить или сделать приватным.

Копии, которые кто-то уже скачал, это не удалит.

## Локальная разработка

```bash
cd server
EXTRA_ORIGINS=http://localhost:8000 SITE_URL=http://localhost:8000/medical_atlas API_URL=http://localhost:8787 \
SECRET=dev-secret-dev-secret-dev-secret-1 STORE=file:./dev-db.json MAIL_TRANSPORT=log node dev-server.js
```

В соседнем терминале, из папки над репозиторием: `python3 -m http.server 8000`. В `auth/config.js` временно укажите `http://localhost:8787`. Письма со ссылками появятся в консоли сервера.

Тесты сервера: `cd server && node --test test/*.test.js`.
