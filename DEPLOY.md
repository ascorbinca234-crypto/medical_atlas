# Вход и закрытые темы: как развернуть

Сайт остаётся на GitHub Pages. Вход и выдача закрытых тем работают в Яндекс Облаке: функция, API-шлюз и база YDB. Данные пользователей хранятся в России.

```
браузер ──► GitHub Pages: хаб, атласы (открытая часть), страница входа auth/
   │
   └──────► API-шлюз ──► функция atlas-api ──► YDB (пользователи)
                              │                 почта (письма)
                              └── закрытые части атласов (внутри функции)
```

Способы входа: почта и пароль, Яндекс ID, VK ID. Google и Apple не подключаются: с 7 июля 2026 года за них штрафуют (ст. 13.55 КоАП).

## Что где лежит

| Путь | Что это |
|---|---|
| `index.html` | Главная: лендинг со встроенным входом, интерактивной схемой и заявкой для преподавателей |
| `landing/` | Стили главной (Tailwind 4). После правок классов в `index.html`: `npm i -D tailwindcss@4`, затем `node landing/build.mjs` |
| `assets/atlas-access.js` | Подписи карточек по подтверждённым правам текущего аккаунта |
| `auth/` | Страница входа и регистрации, `auth.js` — общий клиент входа, `config.js` — адрес API |
| `cabinet/` | Личный кабинет: стрик, опыт и ранг, освоение лекций и разделов, теплокарта, достижения, ординаторская. `cabinet/?demo` — демо с вымышленными данными для показа |
| `progress/progress.js` | Журнал занятий: атласы сообщают о карточках «Учить», освоении разделов и открытой теме; после входа журнал уходит на сервер |
| `privacy.html` | Политика конфиденциальности и текст согласия. **Заполните места, выделенные жёлтым** |
| `server/` | API без сторонних зависимостей (Node.js 18+) |
| `server/content/` | Закрытые части атласов. Создаются при сборке, в git не попадают |
| `farma-atlas/src/` | Два пробных конспекта, заголовки закрытых тем и интерфейс |
| `biochem-atlas/data/` | Два пробных конспекта: классификация аминокислот, глюкоза и фруктоза |
| `medical_atlas_private` | **Отдельная локальная папка закрытых исходников**. Репозиторий с таким именем создавать необязательно |

Закрытая папка кладётся рядом с публичным репозиторием:

```
projects/
  medical_atlas/            ← этот репозиторий (публичный)
  medical_atlas_private/    ← закрытый
```

Другой путь можно задать переменной `ATLAS_PRIVATE=/путь/к/medical_atlas_private`.

## Личный кабинет

Кабинет работает и без входа: прогресс берётся из журнала в браузере (`localStorage`, ключ `ma-progress-v1`). При первом открытии туда переносится история режима «Учить» фармакологии. После входа журнал отправляется на сервер, складывается с другими устройствами, и открывается ординаторская.

Как считается прогресс (правила одинаковые в `progress/progress.js` и `server/src/progress.js`, их сверяет тест):

- 5 XP за карточку в режиме «Учить» любого атласа, +3 XP, если вспомнили;
- цель дня — 10 карточек: день засчитывается в стрик, бонус 20 XP + 2 XP за каждый день стрика (до 20 дней);
- дефибриллятор: 2 заряда, пропущенный день тратит заряд вместо обнуления стрика, +1 заряд за каждые 7 дней стрика;
- освоено (закреплено): карточка дошла до 3-й коробки интервального повторения;
- рукопожатие: +5 XP обоим, раз в день на пару; дуэль: 3 дня, кто больше наберёт XP, победителю +50 XP.

API кабинета (все запросы — с токеном входа):

| Запрос | Что делает |
|---|---|
| `GET /progress`, `POST /progress` | Журнал этого устройства → сервер; в ответ журнал всех устройств, расчёт стрика и опыта, ID в ординаторской |
| `PATCH /progress/profile` | Вуз, курс, статус |
| `GET /social` | Коллеги, рейтинг недели, дуэли, уведомления |
| `GET /social/find?code=MA-123456` | Найти коллегу по ID или ссылке-приглашению |
| `POST /social/friends`, `DELETE /social/friends/MA-123456` | Добавить или убрать коллегу (у обоих) |
| `POST /social/duel`, `POST /social/hand`, `POST /social/seen` | Дуэль, рукопожатие, прочитать уведомления |

Данные кабинета лежат в той же таблице `users` под ключами `doc:p:<id>` (прогресс) и `doc:s:<id>` (ординаторская), ID — в `identities` под ключом `code:MA-…`. Новых таблиц и переменных не нужно. После обновления кода **один раз выложите новую версию функции** (`deploy.ps1` или раздел 6). Пока функция старая, кабинет работает на журнале браузера, а ординаторская пишет, что временно недоступна. При удалении аккаунта прогресс стирается, а пользователь пропадает из ординаторских коллег.

## 1. Закрытые исходники

Полные материалы хранятся в соседней папке `medical_atlas_private`, вне публичного Git:

- `farma-atlas/base/src/` — прежние публичные материалы, модель «Организм» и тренажёр; `farma-atlas/src/` — остальные темы; `manifest.json` перечисляет все обязательные файлы.
- `biochem-atlas/base/` — прежние данные и полный шаблон; `biochem-atlas/data/` и `src/locked.js` — дополнения. Сборка проверяет ссылки во всём наборе.
- `micro-atlas/src/` — 22 темы, досье и вопросы.
- `pathophys-atlas/PathoAtlas.jsx` — исходный полный React-атлас патофизиологии (28 тем). Публичный интерфейс и два открытых урока хранятся в репозитории; остальные уроки и их схемы собираются в отдельные пакеты. Перед сборкой выполните `npm ci --prefix pathophys-atlas`.

Пробные конспекты фармакологии и микробиологии должны совпадать с их частными оригиналами. Полная сборка останавливается при расхождении или отсутствии исходников. Для публичной сборки закрытая папка не нужна.

## 2. Яндекс Облако

На Windows всё из этого раздела и раздела 6 делает скрипт `server/deploy/deploy.ps1`: положите рядом с ним `function.zip` и запустите `powershell -ExecutionPolicy Bypass -File deploy.ps1` (нужна программа `yc` после `yc init`). Ключи и пароли он хранит только на этом компьютере. Таблицы в базе сервер создаёт сам при первом запросе.

Вручную:

Нужен аккаунт в [console.yandex.cloud](https://console.yandex.cloud) с платёжным аккаунтом. Для небольшого проекта бесплатных лимитов Cloud Functions, API Gateway и YDB Serverless обычно хватает.

1. **Сервисный аккаунт** `atlas-api` с ролями `ydb.editor` и `functions.functionInvoker`.
2. **База** → Managed Service for YDB → «Создать базу», тип **Serverless**. На странице базы скопируйте **эндпоинт Document API** (`https://docapi.serverless.yandexcloud.net/ru-central1/…`).
3. **Статический ключ доступа** для `atlas-api`: «Сервисные аккаунты» → `atlas-api` → «Создать новый ключ» → «Статический ключ доступа». Сохраните идентификатор и секрет.
4. **Таблицы** — один раз, на своём компьютере:
   ```bash
   cd server
   YDB_DOCAPI_ENDPOINT=… YDB_ACCESS_KEY_ID=… YDB_SECRET_ACCESS_KEY=… node scripts/create-tables.js
   ```
5. **Функция** → Cloud Functions → «Создать функцию» `atlas-api`. Среда — `nodejs22`, точка входа `index.handler`, память 256 МБ, таймаут 30 с (отправка письма может занять несколько секунд). Код — архив `server/dist/function.zip` (как его собрать — в разделе 6).
6. **API-шлюз** → API Gateway → «Создать». Спецификация — из `server/api-gateway.yaml`, подставьте ID функции и ID сервисного аккаунта. После создания скопируйте домен шлюза вида `https://xxxx.apigw.yandexcloud.net` — это **API_URL**.

2. Базовые домены — оба, без `https://`: домен сайта `ascorbinca234-crypto.github.io` (с него нажимают кнопку, VK проверяет его) и домен API-шлюза `xxxx.apigw.yandexcloud.net` (на нём адрес возврата). 2. Настройки почты → «Почтовые программы» → разрешите доступ по IMAP/SMTP.

Когда у проекта появится свой домен, письма лучше перевести на Yandex Cloud Postbox.

## 6. Переменные функции и выкладка

В настройках функции задайте переменные окружения. Секреты лучше хранить в Lockbox и подключать к функции оттуда.

| Переменная | Значение |
|---|---|
| `SITE_URL` | `https://ascorbinca234-crypto.github.io/medical_atlas` |
| `API_URL` | домен API-шлюза |
| `SECRET` | случайная строка от 32 символов: `openssl rand -base64 48`. Смена выкидывает всех из аккаунтов |
| `YDB_DOCAPI_ENDPOINT`, `YDB_ACCESS_KEY_ID`, `YDB_SECRET_ACCESS_KEY` | из шагов 2–3 |
| `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` | из шага 3 |
| `VK_CLIENT_ID` | из шага 4 |
| `SMTP_USER`, `SMTP_PASS` | ящик и пароль приложения из шага 5 |
| `LEAD_TO` | необязательно: куда приходят заявки преподавателей с главной. По умолчанию — тот же ящик `SMTP_USER` |

Сборка и выкладка после любой правки тем:

```bash
# Из корня: четыре публичные пробные версии
python3 build.py
# Из корня: полный комплект и manifest.json; все закрытые исходники обязательны
python3 build.py --full
# Пересобирает полный комплект и создаёт server/dist/function.zip
node server/scripts/package.js
```

Загрузите `function.zip` новой версией функции. Публичные `index.html` атласов закоммитьте в этот репозиторий.

Проверка: `API_URL/health` должен возвращать HTTP 200, `ok:true`, `policy:"subject-subscription-v1"`, `database:true` и четыре значения `content:true`. Ошибка конфигурации, БД или отсутствие полного предмета дают HTTP 503. `API_URL/live` проверяет только работающий процесс и возвращает 200. Проверка готовности не использует старый результат создания таблиц.

В том же ответе `providers` показывает, какие входы включены. `"vk": false` значит, что в выложенной версии функции нет `VK_CLIENT_ID`: в `deploy.ps1` на вопросе «ID приложения VK ID» введите ID приложения.

Если письмо с кодом не дошло, причина видна на экране ввода кода («Подробности для разработчика») и в логах функции (строка `mail failed`). Каждое письмо приходит с новым кодом; действуют три последних.

## 8. Доступ к материалам и порядок обновления

`GET /content-v2/<subject>` и старый `GET /content/<subject>` требуют токен и действующее право именно на запрошенный предмет. Регистрация прав не выдаёт. `GET /access` возвращает каталог и права текущего пользователя. Идентификаторы: `farma`, `biochem`, `micro`, `pathophys`, `biology`. Биология ещё не имеет материалов; патофизиология содержит 28 тем и два открытых урока. Продажи подписок ещё не открыты.

Права — серверный документ `access:<userId>` (в YDB это строка `doc:access:<userId>` таблицы users):

```json
{"farma":{"expiresAt":1793440800000,"revoked":false},"micro":{"expiresAt":1796032800000}}
```

`expiresAt` — конечный момент в миллисекундах Unix. Нет права, срок истёк или `revoked:true` — HTTP 403. Пример не является командой выдать доступ. Изменять права может только доверенная серверная логика: публичного API для выдачи нет. Будущий обработчик платежей записывает отдельное право на каждый купленный предмет, включая комплект. Платежи и автопродление пока не подключены.

1. Собрать и загрузить новый `function.zip` в существующую облачную функцию с сохранением её настроек.
2. Проверить `/health`, отказ для аккаунта без подписки и доступ тестового аккаунта только к назначенному предмету.
3. Опубликовать публичные страницы. Новый клиент использует только `/content-v2/` и требует заголовок политики; со старым сервером показывает пробную версию. Старый URL тоже нужно защитить обновлением сервера — изменение одного сайта его не закрывает.

Клиент больше не читает и не записывает закрытые материалы в IndexedDB и удаляет старую базу кэша. При открытии, возврате к вкладке и периодически во время просмотра проверяет доступ; выход и истечение срока перезагружают страницу. Уже сохранённые кем-либо копии эти меры не отзывают.

## 9. Старые версии в истории Git

Полные материалы ранее публиковались и остаются в старых коммитах. Удаление из текущей версии не очищает историю и чужие копии. Решение о видимости репозитория или переносе в новый репозиторий принимает владелец отдельно. Обычная сборка и выкладка историю не переписывают.

## Локальная разработка

```bash
cd server
EXTRA_ORIGINS=http://localhost:8000 SITE_URL=http://localhost:8000/medical_atlas API_URL=http://localhost:8787 \
SECRET=dev-secret-dev-secret-dev-secret-1 STORE=file:./dev-db.json MAIL_TRANSPORT=log node dev-server.js
```

В соседнем терминале запускайте статический сервер только с публичными путями; не раздавайте каталог `server/` и соседнюю папку закрытых материалов. В `auth/config.js` временно укажите `http://localhost:8787`. Письма со ссылками появятся в консоли сервера.

Тесты сервера: `cd server && node --test test/*.test.js`.

Файловое хранилище предназначено для локальной разработки в одном процессе. Повреждённая база вызывает ошибку запуска и остаётся на диске без изменений. SMTP ограничен общим сроком 20 секунд, внешние HTTP-запросы — 8 секунд. Это не заменяет отдельные нагрузочные проверки, резервные копии и мониторинг перед продажами.

## Администратор материалов

Администратор читает все опубликованные атласы без подписки. Этот аккаунт не предоставляет доступ к инфраструктуре или чужим профилям. Флаг `contentAdmin` хранится только на сервере; регистрация и изменение профиля не могут его назначить.

Для однократного создания задайте в функции `ADMIN_BOOTSTRAP_EMAIL` (логин в формате почты), `ADMIN_BOOTSTRAP_PASSWORD_HASH` (scrypt-хеш из `server/src/passwords.js`) и при необходимости `ADMIN_BOOTSTRAP_ID` (по умолчанию `atlas-content-admin-v1`). Пароль и хеш не включаются в публичный Git или архив функции. При первом вызове создаётся отдельный аккаунт и постоянная отметка о выполненной настройке. Повторный запуск сохраняет изменённые реквизиты; удаление или отзыв админского флага не отменяются повторной настройкой. Уже занятый логин не получает привилегий.

В разделе «Аккаунт» администратор может поменять логин и пароль, указав текущий пароль. Остальные сессии при этом отзываются. После успешного создания переменные bootstrap можно удалить: аккаунт остаётся в базе.

Бесплатная Фарма теперь включает модель «Организм» и анимации эффектов 176 препаратов, в том числе прямые ссылки на них. Закрытые конспекты, подробные досье и рецепты не публикуются.
